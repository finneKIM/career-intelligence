### 4. 아직 확인하지 못한 것 (반드시 확인)
1. **노션 가져오기 결과의 필드별 정확성**: 실DB 불러오기(74행 감지)는 사용자가 확인했으나 기간·기술 스택·성과가 원본과 일치하는지 항목별 대조 기록은 없음
2. **브라우저 UI 중 AI 관련 화면**: 설정 탭 AI 항목(동의, 모델 드롭다운), 공고 등록 AI 버튼, 매칭 리포트 AI 분석, 성과 다듬기, "사용 모델" 표시를 각각 확인했는지는 기록되지 않음
3. **Vercel 배포 환경**: 브라우저에서 CSP로 화면이 깨지지 않는지, 배포본에서 방문자 키로 AI 실호출·노션 실호출, 응답 시간, Vercel의 Fluid compute·Max Duration 설정(공식 문서상 Fluid 기본 활성이면 Hobby도 300초라 40초 예산은 들어감), 레이트 리밋은 인스턴스별 best-effort, 배포된 서버에서 Neon에 접속되는지(앱이 DB를 쓰는 코드가 없어 미시험)
4. **실패 모델 기억의 운영 효과**: 서버리스 인스턴스가 바뀌면 초기화되므로 배포 환경에서의 효과는 알 수 없음
5. **계정 기능 관련**: (확인됨 2026-11-06) 파생값 비밀번호 수용·세션 검증·Neon 실제 DB 동작은 Better Auth로 확인. **남은 것**: Vercel 실제 함수에서 `/api/account/*` rewrite 동작, 메일 발송 방법·도메인 요건(도메인 구입 후), 암호화 코드의 외부 보안 검토(미실시), 휴대폰 키 파생 시간, 처리방침 법률 검토
6. **파일 출력 관련**: 구형 `.ppt`는 지원하지 않기로 구현함(사용자 확인 대기). DOCX·PPTX는 파일 구조·한글 포함을 자동 시험으로 확인했으나 Word/PowerPoint에서 열었을 때의 모양, PDF(브라우저 인쇄)의 한글 표시는 직접 확인하지 못함

### 5. 주의사항
- 개발 서버(Vite)는 **OS 환경 변수**(예: 셸에 설정된 `GEMINI_API_KEY`)와 `.env.local`도 서버 핸들러에서 읽음. 접근 코드가 맞으면 운영자 키로 실제 Gemini 호출이 발생함
- 비밀 값은 GitHub에 올리지 않음. `VITE_` 접두사에 비밀 값 금지. `.env.local`·`.vercel/`은 `.gitignore` 대상
- Neon 연결 문자열·키는 채팅·문서·GitHub에 노출하지 않음. 로컬 시험은 `.env.local`에 넣지 않고 `vercel env run -- <명령>`으로 실행 중에만 주입
- `vercel link`/`install` 계열 명령은 `.env.local`·`.gitignore`를 건드릴 수 있어 실행 전 백업·실행 후 확인 필수(이번에 `.gitignore`의 `.env*` 줄이 `.env.example`을 무시하게 만드는 부작용을 되돌림)
- 무료 Gemini 티어는 입력이 서비스 개선에 쓰일 수 있음 → UI에서 동의 체크 후에만 AI 동작
- 방문자 키·토큰은 호출 때 서버를 한 번 통과함(저장·로그 없음). 서버 운영자가 코드를 바꾸면 볼 수 있다는 구조적 한계를 화면에 고지함
- 커밋 이메일은 GitHub noreply 주소(2026-11-05 교체). 새 커밋도 이 저장소 설정으로 noreply 사용
- **개발 서버 운영 규칙**: 시험용으로 띄운 서버는 시험 직후 종료하고, 사용자가 보고 있는 메인 서버(포트 5173)는 사용자가 끄라고 하기 전까지 유지. 이 환경(Git Bash)에는 `pkill`이 없어 종료는 PowerShell로 함
- 실제 키로 외부 API를 호출하는 시험은 사용자의 허락을 받고 진행. 커밋·푸시는 지시가 있을 때만. 푸시는 `main`만
- 시험용 임시 파일(PGlite 설치, 검증 스크립트, 호스트명 패치)은 저장소 밖 세션 임시 폴더에 있으며 커밋 대상이 아님. 필요하면 재현 방법은 `DEPLOY.md`·`DEV_PLAN.md` 참고
