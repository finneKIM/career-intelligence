# 제품 요구사항 정의서 (PRD.md)

이 문서는 **Career Intelligence**의 제품 요구사항, 타겟 사용자, 핵심 기능 명세, 사용자 여정 및 세부 정책을 정의하는 단일 진실 공급원(SSoT) 기준 문서입니다.

---

## 1. 타겟 사용자 (Target User)

### ① 주요 사용자층
- **테크 분야 구직자 및 이직 준비자**: 신입, 주니어~미드레벨 개발자(AI/데이터/백엔드/프론트엔드 등).
- **커리어 전환자**: 인접 분야나 테크 직무로 전환을 준비하며 자신의 기존 경험을 어떻게 어필할지 고민하는 구직자.

### ② 사용자 페르소나
> **페르소나: 이지은 (2년 차 데이터 분석가 / AI 엔지니어 전향 희망)**
- **상황**: 데이터 분석 업무를 하다가 AI/ML 엔지니어로 커리어 도약을 준비 중. 여러 채용 공고를 보며 지원서를 내고 있지만, 합격/불합격의 명확한 이유나 부족한 점을 객관적으로 알기 어려움.
- **불편사항 (Pain Point)**:
  - 노션, 엑셀, 폴더에 공고와 자소서가 흩어져 있어 지원 히스토리 관리가 번거로움.
  - 시중 매칭 서비스는 'Python' 단어만 보고 무조건 적합하다고 하지만 실제 면접에서는 모델 서빙 경험 부족으로 탈락함.
  - 내 경험으로 AI 엔지니어 외에 MLOps나 Data Platform 쪽도 가능한지 시야를 넓히고 싶음.
- **원하는 가치**: "내 프로젝트와 경력을 바탕으로 실제 증명할 수 있는 역량과 부족한 부분을 객관적으로 짚어주고, 지원 이력을 한곳에 안전하게 남겨두고 싶다."

## 2-1. [상세 기능 명세] 1. 커리어 프로필 & 프로젝트 자산 관리

### ① 비즈니스 규칙 및 데이터 정합성 정책
1. **단일 로컬 프로필 정책**:
   - 로컬 퍼스트 환경 특성상 기본 프로필 ID는 `'current-user'` 고정 단일 레코드로 유지되며, 프로필 수정 시 덮어쓰기 형태로 즉시 로컬 DB에 반영됩니다.
2. **기술 스택(Tech Stack) 입력 규칙**:
   - 단순 텍스트 서술이 아닌 태그 배열(`string[]`)로 강제하여 추후 JD 매칭 엔진에서 단어 토큰 단위로 정확히 분리·대조할 수 있도록 보장합니다.
   - 대소문자를 구분하지 않고 중복 입력을 자동 제거합니다 (예: `pytorch`, `PyTorch` 입력 시 하나로 통합 정규화).
3. **수행 성과(Outcomes) 불릿 분리 입력 원칙**:
   - 긴 줄글 자기소개서 형태가 아니라, **최소 1개 이상의 개별 불릿 항목(`outcomes[]`)**으로 나누어 저장합니다.
   - 각 불릿에는 '정량적 수치(예: %, ms, 건수)'나 '구체적 역할'을 담도록 입력창 하단에 안내 팁을 제공합니다.
4. **프로젝트 수행 기간(Period) 유효성**:
   - `startDate`는 필수이며, `endDate`는 진행 중(`isOngoing=true`)일 경우 비어둘 수 있습니다.
   - `startDate`가 `endDate`보다 미래 시점일 수 없습니다.
5. **프로젝트 삭제 정책**:
   - 프로젝트를 삭제하더라도, 이미 지원 이력 트래커(Application Tracker)에 '스냅샷'으로 박제된 과거 지원 건의 데이터에는 영향을 주지 않습니다 (독립 스냅샷 불변성 원칙).

## 2-2. [상세 기능 명세] 7·8. 기업 자료 수집·분석 & 맞춤 문서 생성 (2026-11-06 승인 확장 · 구현 전)

> 5일 MVP 범위를 넘는 확장이며 사용자가 2026-11-06에 승인했습니다. **로컬(브라우저) 우선**으로 설계하며, 계정·암호화 저장(9번 기능, Neon DB 연결 완료)도 같은 날 방향이 승인되어 §5의 Phase 1.6으로 함께 진행합니다. 두 기능의 선후는 확정됨(2026-11-06): 7-0 → 7-1~7-5 → 이 기능(`DB_IMPLEMENTATION_PLAN.md`). 아래는 구현 전 요구사항이며, 구현하면서 확인된 사실에 따라 갱신합니다.

### ① 사용자가 확정한 결정 사항
| 항목 | 결정 |
| :--- | :--- |
| 개발 순서 | 로컬 기능을 먼저. 계정·클라우드 DB는 이후 |
| 기업 자료 수집 | 사용자 붙여넣기·URL 목록을 기본으로 시작. 검색 연동은 후속 선택 기능 |
| 생성 순서 | 이력서 → 포트폴리오. **필요한 문서만 선택 생성** (이력서만도 가능). 자소서도 같은 선택 옵션에 포함 |
| 출력 형식 | 이력서·자소서: **PDF, Word(.docx)** / 포트폴리오: **PDF, PPTX, PPT** |
| LLM 요금제 | **무료 티어를 기본**으로 하되, 사용자가 선택해 유료 티어를 쓸 수 있게 함 (§⑦) |

### ② 입력 자료
- 프로젝트 자산(기존), 노션 DB(기존 — **DB 속성만 읽음**, 페이지 본문 읽기는 후속·선택)
- **과거 이력서·자소서·포트폴리오 원문(신규)**: 1차는 텍스트 붙여넣기. PDF·Word 파일 읽기 여부는 미결(사용자의 자료 형태 확인 필요)
- 채용 공고(기존, 붙여넣기·AI 구조화). **공고 URL 자동 수집은 현재 구현되어 있지 않음** (안내 문구만 있음)
- 기업 자료(신규): 사용자가 붙여넣은 홈페이지·기업 소개·뉴스 텍스트와 URL 목록

### ③ 기업 자료 수집 정책
- **기본(안정 경로)**: 사용자 붙여넣기·URL 목록 → 100% 동작, 접근 제한 우회 없음 (`AGENTS.md` 9절)
- **후속 선택 기능**: Gemini의 Google 검색 연동(Grounding)·URL 읽기 도구, 공시 API(OpenDART). 이 중 Grounding은 3세대 Flash 무료 티어에서 사용 불가이며 유료 티어는 월 5,000건 무료(공식 문서, 2026-11-06 확인). 서버가 임의 사이트를 직접 크롤링하는 방식은 약관·`robots.txt`·보안(임의 주소 호출 위험) 문제로 **채택하지 않음**
- 모든 수집 건에 **출처 URL·수집일·상태(직접 입력/수집 성공/실패와 원인)** 를 기록
- 저작권을 고려해 **원문 전체가 아닌 짧은 발췌·요약·링크**만 저장 (법률 자문 아님)

### ④ 분석 (적합도·보완점)
- 기존 3단계 분석(직접/간접/Evidence Gap)을 유지하고, 여기에 **기업 맥락 연결**(기업 자료의 사업·기술과 내 경험의 접점)을 더함
- **합격 확률 표현 금지** 유지. 근거 건수·보완 가이드로만 제시
- 분석 결과는 시점·모델·분석 버전과 함께 저장하며 이후 자료 변경으로 덮어쓰지 않음

### ⑤ 문서 생성 정책 (가장 중요)
1. **근거 기반**: 생성 문장마다 근거(어느 프로젝트·원문의 어느 부분인지)를 연결해 보여줌
2. **날조 금지**: 입력에 없는 수치·회사명·경험은 서버에서 폐기 (기존 "성과 문장 다듬기" 검증을 이력서·자소서·포트폴리오 전체로 확장)
3. **경험 수준 구분**: 직접 경험은 본문에 쓰고, 간접·미확인 역량은 본문에 넣지 않고 "보완 제안"으로만 제시
4. **사람 검수 필수**: AI 결과는 초안(DRAFT). 사용자가 원문과 비교·수정·확정해야 저장 (자동 확정 없음)
5. **개인정보**: 이름·연락처는 AI에 보내지 않고 본문만 생성한 뒤 **브라우저에서 합성**
6. **버전 보존**: 생성 문서는 덮어쓰지 않고 버전으로 저장하며 생성 시점·모델·분석 버전·요금제 선언값을 기록. 지원 이력 스냅샷과 연결 가능 (불변 스냅샷 원칙)
7. 기존 AI 3기능 결과는 지금처럼 **저장하지 않음**을 유지. 생성 문서는 사용자가 "저장"을 눌렀을 때만 저장

### ⑥ 출력 형식과 구현 리스크
| 문서 | 형식 | 구현 메모 (확인 수준) |
| :--- | :--- | :--- |
| 이력서·자소서 | PDF | 브라우저 인쇄(PDF로 저장) 방식을 기본안으로 함. 한글 표시는 시험 필요 |
| | Word(.docx) | `docx` 라이브러리 후보 (MIT, 브라우저 동작 공식 설명 확인, 한글 시험 필요) |
| 포트폴리오 | PDF | 위와 동일 |
| | PPTX | `PptxGenJS` 후보 (MIT, 브라우저에서 .pptx 다운로드 공식 설명 확인, 한글 폰트 처리는 문서에 명시 없어 시험 필요) |
| | **PPT(구형 .ppt)** | ⚠️ **구현 방법 미확인**. 위 라이브러리는 .pptx만 확인됨. 대안 후보: PowerPoint에서 PPTX를 PPT로 저장 안내 / 별도 변환 서비스 / 제외 — 사용자 결정 필요 |

### ⑦ LLM 요금제 선택 (무료 기본 · 유료 선택)
- 기본은 **무료 티어**. Gemini 무료 티어는 입력이 서비스 개선에 사용될 수 있고 유료 티어는 아님 (공식 가격 페이지, 2026-11-06 확인) → 이력서 내용을 다루므로 화면에서 계속 고지하고 동의 후에만 동작
- **앱은 사용자 키의 요금제를 자동으로 알 수 없음.** 따라서 설정 탭에서 "내 키는 유료(결제 연결) 프로젝트입니다"를 **사용자가 직접 선언**하는 방식으로 구현하는 안을 제안하며, 선언에 따라 ① 데이터 이용 안내 문구 변경 ② 유료 전용 옵션(예: Google 검색 연동) 활성화. 이 해석은 사용자 확인 대기 (HANDOVER 질문 목록)

### ⑧ 확인된 제약
- 서버 요청 본문 60KB(한글 약 2만 자) → 관련 근거만 **선별해서** 전송
- 요청당 40초 시간 예산(관측 AI 호출 15~30초) → 단계별 분할 호출과 진행 표시 (Vercel 한도 300초는 문제 아님)
- 무료 티어의 호출 한도 숫자는 공식 문서에 없어 확인 불가 (AI Studio에서 키별 확인)
- AI가 만든 문장의 품질은 검증 코드가 보장하지 못함 — 수치·근거 위반만 차단, 문장의 좋고 나쁨은 사용자 검수

## 3. 사용자 시나리오 (User Journey)

### ① 온보딩 및 프로필 자산 등록
1. 사용자가 서비스에 처음 접속하면 대시보드와 함께 프로필 작성을 유도받습니다.
2. 경력 사항과 함께 수행한 프로젝트(프로젝트명, 기간, 사용 기술 태그, 주요 역할, 정량적 성과)를 입력합니다.
3. 관심 도메인(예: 음성 AI, 헬스케어)과 희망 직무를 등록하여 내 커리어의 기본 데이터베이스를 완성합니다.

### ② 채용 공고(JD) 등록 및 파싱
1. 관심 있는 기업의 채용 공고 링크(URL)를 입력하거나, 공고 텍스트 전문을 복사하여 붙여넣습니다.
2. 파서(Parser)가 공고를 읽고 [주요 업무], [자격 요건], [우대 사항]으로 자동 분류하여 정돈된 화면을 보여줍니다.
3. 사용자가 파싱된 내용을 검토하고 필요 시 직접 수정/보완합니다.

### ③ 3단계 지능형 매칭 & Gap 분석 리포트 확인
1. 사용자의 프로필 자산(프로젝트 성과)과 채용 공고 요건을 대조합니다.
2. 결과 화면에서:
   - **직접 증명 역량**: 실제 프로젝트에서 명확한 성과를 낸 부분 확인.
   - **간접 연결 경험**: 연관 기술을 통해 어필할 수 있는 부분 확인.
   - **증거 공백 (Evidence Gap)**: 공고에서 요구하나 아직 증명되지 않은 역량을 확인하고, 이를 어떻게 자소서/포트폴리오에서 보완할지 액션 플랜을 제시받습니다.

### ④ 지원 이력 기록 및 스냅샷 보존
1. 해당 공고에 지원할 때 제출한 자기소개서 내용과 포트폴리오 링크/파일을 함께 등록합니다.
2. 지원 일자와 지원 상태(서류 접수 완료 등)를 지정합니다.
3. 이 시점의 JD, 제출 자료, 매칭 분석 결과는 **불변 스냅샷**으로 고정되어 나중에 합격/불합격 결과를 확인하고 복기할 수 있습니다.

### ⑤ Career Explorer를 통한 시야 확장
1. 탐색 탭에서 내 기술 스택을 기반으로 도전 가능한 인접 직무(Role)와 산업 분야(Domain)의 교차 매트릭스를 확인합니다.
2. 내가 가진 역량이 다른 유망 시장(예: 로보틱스, 핀테크)에서 어떻게 활용될 수 있는지 발견하고 새로운 채용 공고를 탐색합니다.

### ⑥ 사용자 맞춤형 노션(Notion) 동적 연동 시나리오
1. 사용자가 노션 내부 통합 토큰과 DB ID를 입력하거나(실시간 불러오기), 노션에서 내보낸 CSV/JSON을 붙여넣습니다.
2. 시스템이 사용자의 노션 DB 열(속성 및 타입)을 실시간으로 스캔하여 감지합니다.
3. 사용자가 직관적인 드롭다운 UI를 통해 자신의 노션 열을 [프로젝트명], [기술 스택], [기간], [수행 성과(불릿)]에 1:1로 매핑합니다.
4. 동기화 실행 시 노션에 저장되어 있던 방대한 프로젝트들이 Career Intelligence의 프로젝트 자산으로 완벽히 변환되어 저장됩니다.

### ⑦ 기업 분석 & 맞춤 문서 생성 시나리오 (2026-11-06 승인 · 구현 예정)
1. 사용자가 과거 이력서·자소서·포트폴리오 원문을 등록해 둡니다. (최초 1회)
2. 지원할 공고를 등록하고, 공고 상세에서 기업 홈페이지·기업 소개 등의 URL·텍스트를 붙여넣어 기업 자료를 모읍니다. 시스템이 출처와 함께 요약합니다.
3. 시스템이 공고·기업 맥락과 내 경험의 적합도를 근거와 함께 보여주고 보완할 점을 제시합니다. (합격 확률은 표시하지 않음)
4. 사용자가 필요한 문서만 체크합니다. (이력서 / 자소서 / 포트폴리오)
5. 시스템이 과거 자료에서 관련 근거를 골라 초안을 만들고, 문장마다 근거를 표시합니다. 근거가 없는 내용은 만들지 않고 "보완 제안"으로 따로 보여줍니다.
6. 사용자가 원문과 비교하며 수정·확정하면 버전으로 저장되고, PDF·Word(이력서·자소서) 또는 PDF·PPTX(포트폴리오)로 내보냅니다.

## 4. 정책 및 예외 처리

### ① 데이터 저장 및 프라이버시 정책 (Local-First)
- **로컬 퍼스트 저장**: 자기소개서, 인적사항, 프로젝트 정보 등 모든 데이터는 브라우저 내부의 IndexedDB에만 **저장**되며, **현재** 서버에는 사용자 데이터를 저장하는 DB가 없습니다(Neon DB는 연결만 되어 있고 비어 있음). 계정 기능이 구현·배포되면 가입한 사용자의 암호화된 사본만 서버 DB에 동기화됩니다(아래 "계정 기반 암호화 저장" 참고).
- **기능 실행 시에만 최소 전송 (Opt-in)**: 평소에는 외부 전송이 없습니다. 사용자가 **AI 분석** 또는 **노션 불러오기**를 직접 실행할 때에만 필요한 내용이 서버리스 함수를 거쳐 외부(Google Gemini / 노션)로 전달됩니다. 서버는 이를 저장하거나 기록하지 않습니다.
  - AI 전송 대상: 해당 공고 본문, 프로젝트 제목·기술·성과 문장, 보유 기술. **이름·연락처 등 인적사항은 전송하지 않습니다.** *(현재 구현은 프로필의 이름 칸만 제외하며 프로젝트·공고의 자유 텍스트는 걸러내지 않음 — Phase 7-0에서 등록한 연락처·가림 단어와 이메일·전화·주민번호 형태를 가려서 전송하도록 강화 예정, 구현 전)*
  - (승인 확장, 구현 전) 맞춤 문서 생성 시에는 위에 더해 **선별된 과거 이력서·자소서 문장과 기업 자료 요약**이 전송 대상이 됩니다. 이름·연락처 제외 원칙은 유지하고, 무료 티어 사용 시 입력이 서비스 개선에 쓰일 수 있음을 생성 화면에서 다시 고지합니다.
  - (승인 방향, **구현 전** — 2026-11-06) **계정 기반 암호화 저장**: 가입한 사용자의 데이터는 브라우저에서 암호화한 뒤에만 서버 DB(Neon)에 동기화되며, 서버 운영자는 회사명·제목·본문·날짜·이름·연락처를 읽을 수 없습니다. 서버가 아는 것은 기록 개수·크기·수정 시각·부모-자식 관계뿐입니다. 단 **AI 기능을 쓰는 순간에는 선택된 내용이 복호화되어 서버 함수를 거쳐 Gemini로 전달**됩니다. 이름·연락처는 프로필의 별도 칸에만 두고 AI 전송 전에 본문에서 정확 일치로 치환·재검사하며(이름의 다른 표기나 학교·회사명 같은 간접 정보는 자동으로 가릴 수 없고, 사용자 지정 가림 단어로 보완), 암호 분실 시 복구 키 없이는 복구할 수 없고, 탈퇴하면 즉시 완전 삭제됩니다. **이 방식이 구현되어 배포되기 전까지 서버에는 사용자 데이터가 저장되지 않으며, 위의 "브라우저에만 저장" 정책이 현재 동작입니다.**
  - AI는 설정 탭에서 **데이터 전송 동의**를 체크한 후에만 동작하며, 무료 티어 특성상 입력이 모델 개선에 쓰일 수 있음을 화면에서 고지합니다.
- **데이터 백업 및 복원**: 사용자가 언제든 브라우저를 이동하거나 백업할 수 있도록 전체 데이터를 JSON 형식으로 내보내기/불러오기할 수 있습니다.
- **API 키·토큰 분리 관리 (방문자별 BYOK)**:
  - 방문자마다 노션 계정·DB·Gemini 키가 다르므로, 서버에는 방문자의 비밀 값을 두지 않습니다. 방문자가 화면에 본인의 Gemini 키와 노션 통합 토큰을 입력합니다.
  - 입력한 값은 방문자 브라우저에만 보관합니다(기본: 탭을 닫으면 삭제, "계속 기억하기" 선택 시에만 영구 보관). 호출할 때만 서버를 **한 번 통과**하며 서버는 저장·기록하지 않습니다. 단, 서버를 통과한다는 사실은 입력 화면에서 고지합니다.
  - 운영자 본인의 Gemini 키(서버 환경 변수)는 접근 코드를 아는 경우에만 쓸 수 있고, 공개 배포에서는 등록하지 않는 것을 권장합니다.
  - 어느 값도 백업 JSON·GitHub에 포함되지 않습니다.

### ② 외부 데이터 수집(스크래핑) 및 Fail-Safe 정책
- 채용 사이트 접근 시 `robots.txt`를 엄격히 준수하며 비정상적인 우회 시도를 하지 않습니다.
- 크롤링이 불가능한 사이트이거나 CORS 제약, 네트워크 차단이 발생할 경우 즉시 친절한 안내와 함께 **'직접 복사/붙여넣기 폼'**으로 전환되어 사용자의 작업 흐름이 끊기지 않도록 보장합니다.

### ③ 외부 DB(노션 등) 연동 정책 (동적 스키마 존중)
- **고정 스키마 강제 금지**: 사용자의 기존 노션 템플릿 변경을 강제하지 않으며, 사용자의 컬럼 구성을 최대한 존중하는 동적 매핑(Dynamic Mapping) 인터페이스를 기본 제공합니다.
- **이중 채널 지원**: 브라우저는 노션 API를 직접 호출할 수 없으므로(CORS) 방문자 본인 토큰을 서버리스 프록시로 중계하는 **실시간 연동**을 제공하며, 토큰이 서버를 지나가는 것을 원치 않는 사용자를 위해 노션 CSV/JSON 붙여넣기·파일 방식도 함께 보장합니다.

### ③ 분석 결과의 객관성 및 신뢰성 정책
- 단순 단어 포함 여부로 역량을 과대평가하지 않습니다.
- '합격률 85%'와 같은 근거 없는 합격 예측 수치 표현을 금지하고, '직무 요건 대비 증거 충족도' 및 '보완 추천 사항'으로 객관적 피드백을 제공합니다.

### ④ 과거 지원 자료 불변성(Immutable Snapshot) 정책
- 프로필이나 프로젝트 내용을 나중에 수정하더라도, 이미 지원 완료 처리된 과거 지원 건의 JD 원문, 제출 자료, 당시 분석 결과는 그대로 보존됩니다.

## 5. 단계별 출시 범위 (Release Scope)

- **Phase 1 (5일 MVP)**:
  - 커리어 프로필 & 프로젝트 입력 관리
